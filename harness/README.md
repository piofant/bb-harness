# Общий харнесс Codex ↔ Gemini ↔ Claude

Синхронизация скиллов и MCP для основных задач в bb. Источники правды:

- полные скиллы — `~/.agents/skills`;
- MCP и отключённые скиллы — `~/.codex/config.toml`;
- хуки `UserPromptSubmit` — `~/.codex/hooks.json` (если есть);
- правила — общий `~/AGENTS.md`, подключённый через инструкции bb и Claude.

Харнесс переносит доступ к инструкциям и инструментам. Разные модели всё ещё
могут давать разные ответы; авторизация провайдеров и передача истории остаются
за bb. Сам харнесс не переключает модель и не восстанавливает вход в аккаунт.

## Что синхронизируется

| Компонент | Gemini / Antigravity | Claude |
|---|---|---|
| Скиллы | Все включённые скиллы: короткие карточки со ссылкой на оригинал | Только имена из локального `main_skills.json`: ссылки на оригиналы |
| Скиллы для другого хоста | Пометка `mac_only` направляет через `mac-bridge` | Вместо полной инструкции — карточка с той же пометкой |
| MCP | Записи создаются автоматически через `mcp_bridge.py` | Каждый сервер подключается вручную через тот же мост |
| Контекст из prompt-хуков | Через обёртку плагина Antigravity | Настраивается средствами Claude, отдельно |
| Правила и история | Подключаются в bb | Подключаются в bb / Claude |

Скиллы плагинов должны сначала появиться в `~/.agents/skills`. Харнесс не ищет
их по кэшам плагинов и не сливает разные версии одного скилла: каноническую
копию выбирают до синхронизации. В репозитории нет личного списка скиллов,
описаний из рабочих проектов, конфигов MCP, токенов, логов и кэшей.

## Установка

Проверено на Linux и Python 3.12. Мост использует POSIX-сигналы и `fcntl`;
Windows не поддержан. Для prompt-хуков нужен Node.js 22.13+ с `node:sqlite` и обновлённая обёртка
из [плагина Antigravity](../plugins/antigravity-acp/README.md#shared-prompt-hooks).

Из корня репозитория, на хосте, который запускает модели:

```sh
mkdir -p ~/.agents/harness ~/.agents/skills ~/.claude/skills
cp harness/harness_sync.py harness/mcp_bridge.py harness/requirements.txt ~/.agents/harness/
python3 -m venv ~/.agents/harness/.venv
~/.agents/harness/.venv/bin/python -m pip install -r ~/.agents/harness/requirements.txt
```

Существующий конфиг Codex остаётся на месте. Проверь, что он находится в
`~/.codex/config.toml`. Если нужен основной набор Claude, создай
`~/.agents/harness/main_skills.json` по
[примеру](main_skills.example.json). Имена в примере условные: укажи свои
установленные скиллы. Отсутствующие скиллы не устанавливаются автоматически.
`mac_only` — подмножество `main`; для него нужен свой настроенный `mac-bridge`.
Пометка в карточке — инструкция модели, а не ограничение доступа к хосту.

Необязательный `~/.agents/harness/gemini_skill_descriptions.json` задаёт короткие
описания по [примеру](gemini_skill_descriptions.example.json). Без него описания
берутся из frontmatter скиллов автоматически. Бюджет каталога — 32 000 байт
UTF-8, максимум 300 байт на исходное описание; полные инструкции не сокращаются.
Это обходит наблюдавшееся в Antigravity отсечение длинных описаний. Поведение
каталога и его лимиты могут отличаться в других версиях провайдера.

```sh
~/.agents/harness/.venv/bin/python ~/.agents/harness/harness_sync.py --check
~/.agents/harness/.venv/bin/python ~/.agents/harness/harness_sync.py
~/.agents/harness/.venv/bin/python ~/.agents/harness/harness_sync.py --check
```

Первый `--check` возвращает 1, если нужно что-то изменить, и ничего не пишет.
После применения ожидается `drift 0 change(s)`. Новые конфиги подхватываются
при старте новой сессии провайдера; уже открытые сессии могут хранить прежний
список инструментов и скиллов.

## MCP и ограничения инструментов

`mcp_bridge.py <имя>` читает определение сервера из конфига Codex во время
запуска. В Gemini и Claude попадают только команда моста и имя сервера.
Поддержаны stdio и streamable HTTP с JSON/SSE-ответами, сессиями, повторной
инициализацией после истечения сессии и повторами при HTTP 429/503.
HTTP-перенаправления не выполняются.

`enabled_tools` и `disabled_tools` проверяются при выдаче списка и при каждом
`tools/call`. Например, для аккаунта с доступом только на чтение укажи в
**своём** конфиге Codex:

```toml
[mcp_servers.work_messages]
command = "/absolute/path/to/your/mcp-server"
enabled_tools = ["find_chats", "get_messages"]
tool_timeout_sec = 60
```

Имена инструментов и команду замени на реальные. Неизвестный ключ конфигурации
останавливает мост: новые настройки доступа не должны молча игнорироваться.
Сервер получает базовые переменные окружения и явно заданные `env` / `env_vars`.
Фильтр действует только на пути через MCP-мост; он не ограничивает шелл агента
или прямой доступ к незащищённому HTTP-серверу.

У Claude подключи каждое нужное имя отдельно (пример для команды выше):

```sh
claude mcp add -s user work_messages -- "$HOME/.agents/harness/.venv/bin/python" "$HOME/.agents/harness/mcp_bridge.py" work_messages
```

Если имя уже подключено напрямую, сначала проверь `claude mcp list`, сохрани
прежнюю настройку и замени её в том же scope. Новый сервер Codex появляется
у Gemini автоматически, у Claude требуется эта команда. Удаление или отключение
сервера в Codex запрещает его запуск через мост, даже если запись Claude осталась.

Для stdio-серверов включён ленивый запуск: после первого полного рукопожатия
последующие сессии получают стартовые ответы из кэша, а процесс поднимается при
первом запросе, которому нужен сервер. Кэш привязан к конфигурации и свеж не
более суток. Ошибки списков не сохраняются, сбой старта сбрасывает кэш, успешная
проверка одинаковых ответов продлевает свежесть. Изменение списка инструментов
вызывает `notifications/tools/list_changed`. HTTP-серверы не используют этот кэш.

Переменные окружения моста:

| Переменная | Значение по умолчанию |
|---|---|
| `HARNESS_CODEX_CONFIG` | `~/.codex/config.toml` |
| `HARNESS_MCP_LOG` | `~/.agents/harness/logs/mcp_bridge.jsonl` |
| `HARNESS_MCP_CACHE_DIR` | `~/.agents/harness/state/mcp-cache` |
| `HARNESS_MCP_LAZY` | `1`; `0` отключает ленивый запуск |
| `HARNESS_MCP_HTTP_TIMEOUT` | `300` секунд на HTTP-операцию |
| `HARNESS_MCP_RETRY_DELAYS` | `2,5` секунд |

Для нестандартного конфига укажи `--codex-config` синхронизации **и**
`HARNESS_CODEX_CONFIG` в окружении процесса моста. Первый флаг сам по себе не
меняет конфиг, который прочитает мост в новой сессии.

Лог содержит имена методов и инструментов, длительность и статус, без аргументов
и результатов; ротация — после 20 МиБ. Файлы лога и кэша создаются с правами
0600. Кэш содержит ответы рукопожатия и списки инструментов, ресурсов и промптов:
он не копирует конфиг, но сервер сам может вернуть чувствительные метаданные.
Не публикуй эти файлы.

## Хуки базы знаний и общие правила

Синхронизация переносит только командные `UserPromptSubmit`-хуки из
`~/.codex/hooks.json` в `~/.gemini/config/prompt_hooks.json`. Схема исходного
файла совпадает с [примером хука базы знаний](../agents/claude-settings.example.json).
Для Claude настрой тот же хук в его settings отдельно. Сам движок и установка
базы знаний описаны [здесь](../knowledge-base/README.md).

Обнови и переустанови обёртку Antigravity по инструкции плагина. Она выполняет
доверенные команды хуков и добавляет `additionalContext` отдельным помеченным
блоком. Общий лимит времени — 5 секунд, контекста — 10 000 символов. Это не
механизм одобрения инструментов; ошибки хуков пропускают исходный запрос.

Общие правила можно подключить из `~/.bb/AGENTS.md` указателем на `~/AGENTS.md`;
Claude также может читать их из своего `~/.claude/CLAUDE.md`. Скрипты этой папки
файлы правил не редактируют. При переходе на другую модель в bb передавай ссылку
на исходный тред; новая модель восстанавливает решения через `bb thread log`.
Это проверялось в обе стороны Codex ↔ Gemini, а доступ Claude к общим MCP и
скиллам проверялся отдельно. Автоматического переноса всех внутренних состояний
между провайдерами здесь нет.

## Автосинхронизация через systemd

Необязательно, Linux с пользовательским systemd. После установки скриптов
скопируй [юниты](systemd) из репозитория:

```sh
mkdir -p ~/.config/systemd/user
cp harness/systemd/harness-sync.* ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now harness-sync.path harness-sync.timer
systemctl --user start harness-sync.service
```

Юниты используют `%h` и установленный выше venv. `.path` следит за каталогом
скиллов, конфигом Codex, хуками и двумя локальными JSON-файлами. Вложенные правки
скиллов подхватывает таймер раз в 10 минут. Диагностика:

```sh
systemctl --user status harness-sync.path harness-sync.timer
journalctl --user -u harness-sync.service -n 30
```

## Сохранность и откат

Чужие каталоги, симлинки и MCP-записи скрипт сохраняет. Только свои карточки,
точные ссылки и записи на этот мост обновляет или удаляет. Claude дополнительно
учитывает их в `~/.claude/skills/.harness_sync.json`. Запись намерений до изменения
помогает восстановиться после сбоя; переход `main` ↔ `mac_only` меняет тип записи.
Пустой или отсутствующий список `main` отключает изменения Claude, включая
уборку старых записей. Манифест не следует править вручную.

Перед применением входные файлы проверяются без записи; повреждённый конфиг
останавливает прогон. Отказ диска во время применения всё ещё может оставить
частичные изменения: общего транзакционного отката для всех файлов нет.
Повторный запуск восстанавливает учёт управляемых записей Claude.

Перед первой синхронизацией сохрани свои настройки Gemini и Claude в закрытом
локальном бэкапе. Для отката останови `harness-sync.path` и `harness-sync.timer`
(если включал), восстанови настройки и убери только созданные харнессом записи.
Удаление скриптов само по себе не удаляет ссылки из конфигов моделей.

## Проверка исходников

Из корня репозитория:

```sh
python3 -m venv /tmp/bb-harness-tests
/tmp/bb-harness-tests/bin/python -m pip install -r harness/requirements-dev.txt
/tmp/bb-harness-tests/bin/python -m pytest -q -p no:cacheprovider harness/tests
cd plugins/antigravity-acp
npm ci
npm test
```

Тесты изолируют домашний каталог, запускают временные MCP-серверы и локальный
HTTP-сервер. Реальные аккаунты и MCP-конфиги для них не нужны. Проверяются
фильтры инструментов, сбои процессов и HTTP, таймауты, кэш, сохранность чужих
записей, манифест Claude, бюджет описаний и вставка контекста в ACP.
