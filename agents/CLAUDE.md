# Пайплайн Claude Code

Положи в `~/.claude/CLAUDE.md`. Общие правила — в [AGENTS.md](AGENTS.md), здесь то, что специфично для Claude Code.

## Масштаб по риску (выбрать до старта)

| Задача | Что делать |
|---|---|
| Вопрос, разбор текста | Прямой ответ; инструменты только по необходимости |
| Понятная локальная правка | Сразу реализация → targeted tests → самопроверка diff |
| Фича или изменение поведения | Полный пайплайн ниже |
| Высокий риск (auth, права, персональные данные, миграции, рассылки, прод) | Полный пайплайн + план изменений и профильные проверки |

## Пайплайн (фичи и поведение)

1. **Product thinking** — для кого, какую проблему решаем: ПРОБЛЕМА → ГИПОТЕЗА → как мерить успех.
2. **Brainstorm** (`superpowers:brainstorming`) — только при реальной неопределённости: 2–3 подхода с trade-offs и рекомендацией; очевидное — выбрать и идти.
3. **Spec** (`superpowers:writing-plans`) — user stories с Gherkin-критериями, тест-кейсы до кода; задачи с зависимостями, параллельные помечены.
4. **Implement** — сам или субагентами (Agent tool) параллельно на независимых частях; долгие прогоны — в фоне. RED-тест на баг.
5. **Review** — один независимый ревьюер, только чтение: логика и edge cases → безопасность → качество. Параллельно с полными тестами, а не после.
6. **Test** — лестница targeted → impacted → full (см. AGENTS.md).
7. **Live E2E** — для изменений поведения: настоящий процесс против фейкового внешнего API и сценария пользователя.
8. **Deploy** — по правилам проекта; проверить статус сервиса и логи без трейсбеков.
9. **Docs** — документация фичи и короткий продуктовый апдейт: ПРОБЛЕМА → ГИПОТЕЗА → РЕШЕНИЕ → МЕТРИКИ.
10. **Verify** (`superpowers:verification-before-completion`) — доказательства, а не утверждения; перечитать план и проверить каждую цель.

## Когда что использовать

| Ситуация | Действие |
|---|---|
| Новая фича | product thinking → brainstorming |
| Архитектурное решение | `think-through:deep-thinking` |
| 2+ независимых подзадачи | параллельные субагенты в одном ходе |
| Любой баг | `superpowers:systematic-debugging` (сначала причина) |
| После кода | один независимый ревьюер |
| Перед «готово» | `superpowers:verification-before-completion` |
| Документация библиотеки | `context7` |

## Чеклист после каждого кода

1. Edge cases — пустые входы, None, границы
2. Ошибки — что сломается и как восстановиться
3. Конкурентность — гонки в async
4. Целостность данных — дубли, сироты
5. Безопасность — инъекции, утечки секретов
6. Производительность — N+1, неограниченная память
7. Мёртвый код

## Общение

- Отвечать на языке пользователя; сначала ответ, коротко; статусы по ходу — одной строкой.
- При фиксе багов — до/после с доказательством.
- Файлы в ответе — markdown-ссылкой с абсолютным путём.
