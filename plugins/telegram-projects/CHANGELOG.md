# Changelog

## Unreleased

Photos and files from Telegram. A photo, document, audio file, video or video note sent to the bot goes to the BB chat as an attachment (uploaded to the project's BB attachments, as BB's composer does) with its caption as the message text; without a caption the text names the file. An album, which Telegram sends as one update per file, goes as one message once no file has arrived for 1.5 s, and a message sent after it waits for it. A file over 20 MB — Telegram's limit for bots — or one that fails to download cancels the whole message, with a word on what to do. A caption is never a bot command. A file in reply to a question card is refused: answers are text. Audio files now go as files instead of being transcribed; voice notes are transcribed as before. A restart during an album gives one notice, and handled messages keep no file ids. An iPhone HEIC photo sent as a file goes as a plain file, since BB takes no HEIC images; a file BB refuses is named and the message is not sent. A file or a voice note in reply to a Lane Pilot phase message is refused too (a voice reply used to vanish without a word), once per album. Downloads of one message share a three-minute deadline, with their own message when it runs out. A download Telegram drops, or an upload a busy BB server misses, is tried twice more (after 2 s and 5 s); a refusal or BB's own 75-second timeout is not. `chat-status` counts these tries (`fileRetries`). A message the bridge cannot take is answered once and passed, and a `/tasks` reply Telegram refuses no longer holds the updates after it.

Фото и файлы из Telegram. Фото, документ, аудиофайл, видео или кружок, отправленные боту, уходят в чат BB вложением (загружаются во вложения проекта BB, как из поля ввода BB), подпись становится текстом сообщения; без подписи текст называет файл. Альбом, который Telegram присылает по одному обновлению на файл, уходит одним сообщением, когда 1,5 с не приходит новых файлов; сообщение, отправленное после альбома, ждёт его. Файл больше 20 МБ (предел Telegram для ботов) или не скачавшийся отменяет всё сообщение, и бот говорит, что делать. Подпись никогда не считается командой. Файл в ответ на карточку вопроса не принимается: ответ — текстом. Аудиофайлы теперь идут файлами, а не расшифровкой; голосовые расшифровываются, как раньше. Перезапуск во время альбома даёт одно уведомление, а обработанные сообщения не хранят id файлов. Фото с айфона в HEIC, отправленное файлом, уходит обычным файлом: картинки HEIC BB не принимает; файл, который BB не принял, бот называет, и сообщение не уходит. Файл или голосовое в ответ на сообщение фазы Lane Pilot тоже не принимаются (голосовой ответ раньше пропадал молча), на альбом — один отказ. На скачивание файлов одного сообщения — три минуты, и если не уложились, бот так и говорит. Скачивание, которое оборвал Telegram, и загрузку, которую пропустил занятый сервер BB, бот повторяет ещё два раза (через 2 и 5 с); отказ и собственный 75-секундный таймаут BB не повторяются. `chat-status` считает эти повторы (`fileRetries`). Сообщение, которое мост не может принять, получает один ответ и пропускается, а ответ на `/tasks`, который Telegram отклонил, больше не задерживает следующие сообщения.

One pinned chat. The new setting «Один закреплённый чат» (`pinnedChat`, off by default) works with the one-chat layout: everything the owner sends the bot goes to one BB thread. A reply to another chat's card goes to that chat once and leaves the pinned chat where it is; `/history` and `/stop` in such a reply act on the replied chat. A reply to an earlier pinned chat that is now closed comes to the pinned one; a closed chat of another agent is refused, so its words never steer the pinned chat. «Подключить здесь» on report cards no longer moves the pin, even on cards sent before it; `/chats` still does. Before a message, an archived pinned chat comes back from the archive while its environment exists; a deleted, hidden or torn-down one, or one BB refuses to unarchive, gives way to a new chat in the same project, started by that message, and the old chat's queued answers still arrive. A passing read failure never replaces the chat; a removed project asks for another. An answer to a question card never revives a chat or starts one. After `/disconnect` the next message starts a new chat at once; `/menu` on a closed pinned chat says what the next message will do. `chat-status` lists the last pin changes and their reasons (`pinEvents`). `bb telegram-projects chat-pin <thread-id>` pins the bot chat to a thread from the CLI (with `pinnedChat`), recorded in `pinEvents`.

Agent replies keep their formatting. Without Rich Messages the reply's Markdown went out as raw text (`**`, `>`, `---`); now it goes as Telegram HTML: bold, italics, strikethrough, code and code blocks, quotes, headings, lists, tables as rows, links, rules. A part Telegram cannot parse goes as plain text, as before.

Один закреплённый чат. Новая настройка `pinnedChat` (по умолчанию выключена) для режима одного чата: всё, что владелец пишет боту, идёт в один чат BB. Ответ на карточку другого чата уходит в тот чат один раз, закреплённый чат не меняется; `/history` и `/stop` в таком ответе относятся к тому чату. Ответ на прежний закреплённый чат, который уже закрыт, приходит в текущий; закрытый чат другого агента — отказ, чтобы чужие слова не управляли закреплённым чатом. Кнопка «Подключить здесь» на карточках больше не меняет закреплённый чат, даже на старых карточках; `/chats` — меняет. Перед сообщением закреплённый чат из архива возвращается, пока цело его окружение; удалённый, скрытый, с удалённым окружением или который BB отказался вернуть сменяется новым чатом в том же проекте — с этим сообщением, а ответы старого чата из очереди всё равно приходят. Кратковременный сбой чтения чат не заменяет; удалённый проект — выбор другого. Ответ на карточку вопроса никогда не возвращает и не начинает чат. После `/disconnect` следующее сообщение сразу начинает новый чат; `/menu` при закрытом чате объясняет, что сделает следующее сообщение. `chat-status` показывает последние смены закреплённого чата и причины (`pinEvents`). `bb telegram-projects chat-pin <thread-id>` закрепляет чат бота за тредом из CLI (с `pinnedChat`), это видно в `pinEvents`.

Ответы агента сохраняют оформление. Без Rich Messages их Markdown приходил сырым текстом (`**`, `>`, `---`); теперь он уходит как HTML Telegram: жирный, курсив, зачёркнутый, код и блоки кода, цитаты, заголовки, списки, таблицы строками, ссылки, разделители. Часть, которую Telegram не разобрал, уходит обычным текстом, как раньше.

## 0.12.0 — 2026-10-24

Lane Pilot phases in the project topics. The plugin reads each project's phases (`phase_list`) with its tasks and sends four new events: the phase moved to a stage, the phase asks a question, the phase waits for the owner's word, the phase closed. A reply to a question message goes to the phase as its answer (`phase_act answer`). A word message has «Да» and «Нет» buttons: «Да» gives the word at once, «Нет» asks for a reply with the reason, which goes to the phase with the «no» (`phase_control word`, with the wave of a wave turn). As with tasks, the first read and a read after 30 minutes of silence send nothing. The task button now opens the run's PM chat instead of the removed Tasks plugin; a phase button opens the Lane Pilot cockpit. The Events tab has a «Фазы» group; turning off task notices no longer stops phase events. Needs Lane Pilot 0.1.292 for the word on the issue and wave turns.

Фазы Lane Pilot в темах проектов. Плагин читает фазы проекта вместе с задачами и шлёт четыре новых события: фаза перешла на стадию, фаза спрашивает, фаза ждёт вашего слова, фаза закрыта. Ответ на сообщение с вопросом уходит фазе как ответ. У сообщения о слове кнопки «Да» и «Нет»: «Да» сразу даёт слово, «Нет» просит ответить с причиной, и причина уходит фазе вместе с «нет». Как и у задач, первое чтение и чтение после 30 минут тишины ничего не шлют. Кнопка задачи теперь открывает чат PM её хода, а не удалённый плагин Tasks; кнопка фазы открывает пульт Lane Pilot. На вкладке «События» новая группа «Фазы».

## 0.11.1 — 2026-10-24

No late task notices after a pause. A read of a project more than 30 minutes after the last one is a silent new baseline: the changes that happened while the plugin was off are history, not news (on re-enabling after three days the plugin queued 928 old task events). A task event that waited in the queue more than 6 hours is dropped, never sent late.

Без запоздалых уведомлений после перерыва. Чтение проекта через 30 минут и больше после прошлого — тихая новая точка отсчёта: изменения за время простоя не шлются (после включения через три дня плагин поставил в очередь 928 старых событий). Событие, пролежавшее в очереди больше 6 часов, выбрасывается.

## 0.11.0 — 2026-10-24

The Telegram part of the SMA map. Another person's private chat with the bot gets one sentence, once (the bot serves its owner only). A sticker, a location or a video note from the owner gets a polite refusal instead of silence. With chat off, a message is answered once an hour that talking to BB from Telegram is off. While BB works on a chat's reply, Telegram shows «typing». A failed getUpdates waits 10 s, doubling to 5 min, instead of 10 s every time. The pairing code is 8 characters and lives 10 minutes. The status says the link state (`off`, `awaiting_code`, `linked`). The new setting «Новый чат из Telegram — только после «да»» (`confirmNewChat`, off by default) keeps the first message of a new chat as a draft until a whole «да».

Часть карты SMA про Telegram. Чужой человек в личке бота получает одну фразу, один раз. На стикер, геометку или кружок владелец получает вежливый отказ, а не тишину. Если общение выключено, бот раз в час отвечает, что оно выключено. Пока BB готовит ответ, Telegram показывает «печатает». После сбоя getUpdates пауза удваивается от 10 с до 5 мин. Код сопряжения — 8 символов, живёт 10 минут. Статус называет состояние связи. Новая настройка `confirmNewChat` (по умолчанию выключена): первое сообщение нового чата ждёт целого «да».

## 0.10.0 — 2026-10-12

Task events now come from Lane Pilot instead of the BB Tasks plugin, which is switched off. The plugin reads each visible project's runs over the Lane Pilot RPC (`list_runs`, `get_run_card`), at most every 15 seconds. A task is its latest attempt: new, started, accepted (done), canceled, and blocked, which is the worker error alert with the block reason. Retries do not alert; each event is sent once. The first read of a project is silent, and the old Tasks snapshots are dropped. `/tasks` and the companion projection list open Lane Pilot tasks. The "needs review" and "due date changed" events are removed, since Lane Pilot has neither. The `tasks_cli_unavailable` problem is now `lane_pilot_unavailable`. No `bb` CLI calls remain.

События задач теперь берутся из Lane Pilot, а не из плагина Tasks, который выключается. Плагин читает ходы проектов по RPC Lane Pilot (`list_runs`, `get_run_card`) не чаще раза в 15 секунд. Задача — её последняя попытка: новая, начата, принята, отменена и заблокирована (это сигнал «Ошибка исполнителя» с причиной блокировки). Повторы попыток не шумят, каждое событие уходит один раз. Первое чтение проекта тихое, старые снимки Tasks удаляются. `/tasks` и проекция для companion показывают открытые задачи Lane Pilot. События «Нужна проверка» и «Изменён срок» убраны: в Lane Pilot их нет.

## 0.9.0 — 2026-10-02

Ready for any BB user. The bot owner is linked with a one-time `/start <code>` from the Connection tab instead of a built-in account; the bot identity is learned from its first token. No personal paths remain: the plugin's own receiver writes incoming messages straight to plugin storage, and the companion folder, SMS topic and time zone are optional settings. The default Env Catalog name is `TELEGRAM_BOT_TOKEN`. Every bot text has an English translation, checked by a test, so English switches the bot menu, topic introductions, cards and messages. README and overview rewritten in English and Russian; MIT license.

Готов для любого пользователя BB. Владелец бота привязывается одноразовой командой `/start <код>` с вкладки «Подключение», а не зашит в код; бот определяется по первому токену. Личных путей больше нет: приёмник плагина пишет входящие прямо в хранилище плагина, а папка компаньона, тема SMS и часовой пояс стали необязательными настройками. Имя токена в Env Catalog по умолчанию — `TELEGRAM_BOT_TOKEN`. У каждого текста бота есть английский перевод, это проверяет тест. README и обзор переписаны на английском и русском; лицензия MIT.

## 0.8.0 — 2026-10-02

Отчёты агентов отправляются нативными Rich Messages: шапка с проектом, разделом, агентом и временем, ответ агента — свёрнутым блоком, где Telegram сам рисует таблицы, заголовки, код и списки; при отказе Rich Messages уходит HTML-версия. Кнопка «🔌 Подключить здесь» подключает тред из отчёта к теме, не затирая сам отчёт. Режим саммери: модель BB, выбранная родным селектором провайдера и модели BB, пишет 3–6 пунктов в скрытом треде; саммери тоже свёрнуто, при задержке больше 3 минут приходит полный ответ. Инфоблок команд на вкладке «Обзор» и меню бота строятся из одного списка, меню сверяется с Telegram. Темы проектов называются без «📂», кнопка «Открыть BB» ведёт на страницу проекта. Исправлено: задача, созданная и закрытая между двумя опросами, теперь даёт и «Задача завершена».

## 0.7.0 — 2026-10-02

Отчёты агентов в темы проектов по событиям BB `thread:changed`: закончил ход, ждёт ответа, остановлен или упал — с подписью проекта, раздела, треда и агента. Вкладка «События» заменяет флаги notifyTasks / notifyWorkerErrors / soundOnReview: каждое событие со своим звуком и фильтром проектов, прежние значения переносятся автоматически. Скрытие проекта или раздела в Project Folders удаляет его тему из Telegram. Страница плагина разделена на вкладки «Обзор», «События», «Темы», «Подключение», «Общие».

## 0.6.0 — 2026-10-02

Работа на хабе после переезда BB. Токен бота берётся из Env Catalog (`TG_AIVECH_BOT`) или задаётся вручную как секретная настройка плагина; закрытый файл `aivech.json` плагину больше не нужен. Плагин сам принимает updates (`telegram-ingress`) и отвечает на `/tasks`; companion переведён в режим только отправки SMS. Пустая база плагина больше не создаёт полный набор тем рядом с существующими: создание ждёт явного подтверждения, `bind` принимает существующую тему. Страница плагина оформлена в стиле Pokecut.

## 0.2.0 — 2026-09-12

Двусторонний транспорт через единственный companion-poller и постоянную очередь. Меню проектов, дополнительные темы, создание и подключение сессий BB, выбор разделов/агентов/моделей, остановка, последний ответ, голос через BB transcription, native Rich Messages, обновляемый статус и обработка простых вопросов/разрешений. Старые кнопки и ответы из прежней привязки больше не выполняют действие в новом разговоре. Сквозной тест текста, повторного подключения и голоса пройден.


## 0.1.0 — 2026-09-12

Первая персональная версия: синхронизация проектов с темами Telegram, уведомления Tasks, постоянная очередь доставки, страница BB и CLI для диагностики/восстановления. Снимок companion-сервиса с командами и маршрутизацией SMS. Документированы исследование рынка, архитектура двустороннего транспорта и этапы развития.

Общение с BB, управление сессиями, разрешения из Telegram, транскрибация и native Rich Messages ещё не входят в эту версию.
